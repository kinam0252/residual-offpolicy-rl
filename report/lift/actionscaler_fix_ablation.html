1. Root Cause: Replay Buffer Action Mismatch

Bug: In ActionScaler mode, online replay stored residual_action (range [-scale, scale]) instead of combined_naction (base_norm + residual). Critic learned Q(s, residual) while actor loss computed Q(s, base+pred) — completely different action spaces.

Why Physical Scale Mode (100% SR) Survived the Same Bug

Physical scale mode stored residual ∈ [-1, 1] and clamp(base+res) ∈ [-1, 1] — both are in similar ranges, so critic accidentally learned a useful signal. ActionScaler mode has residual ∈ [-0.3, 0.3] vs combined ∈ [-1.3, 1.3] — catastrophic mismatch.

Analysis

ActionScaler mode critic uses object_state; physical scale mode did not.

Possible reasons:

  • Smaller residual range (±0.1) → requires precise Q-value gradients → critic needs cube position to give accurate signal
  • Physical scale mode (±1.0) → large corrections possible → "brute force" approach succeeds regardless of Q accuracy
  • Offline data (50%) teaches critic that Q depends on cube position → ActionScaler mode benefits from this, physical mode ignores it

This is a positive signal: the critic is learning a more informative value function. For real-world transfer, object state estimation quality becomes critical.

Replay Buffer Consistency (ActionScaler mode)

1. Online replay stores:  [pos_norm_combined(3), euler_delta(3), grip_norm_combined(1)]
2. Offline replay stores: [pos_norm_base(3), 0(3), grip_norm_base(1)]  (zero residual)
3. obs.base_action:       [pos_norm(3), 0(3), grip_norm(1)]
4. Actor output:          [Δpos(3), Δeuler(3), Δgrip(1)] in [-scale, scale]
5. Actor loss combined:   base_action + actor_pred → matches replay format ✓
6. Target Q:              next_base + next_pred → same format ✓
