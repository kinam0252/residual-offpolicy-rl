04 - Parallel Evaluation System

Date: 2025-04-17

Goal: How the eval system works — parallel MuJoCo environments for checkpoint evaluation

2. Parallel Execution Model

Key: All N environments step simultaneously in a single env.step(action) call.

Data Flow per Step

  1. Observation: obs is a dict of batched tensors, shape (N, ...)
    • observation.images.front: (N, 3, 84, 84)
    • observation.images.wrist: (N, 3, 84, 84)
    • observation.state: (N, state_dim)
    • observation.base_action: (N, action_dim) — GR00T's base action
  2. Action: agent.act(obs) returns (N, action_dim) — batched residual actions
  3. Step: env.step(action) internally:
    • MuJoCoResidualWrapper combines base + residual for each env
    • MuJoCoVecEnv loops over _apply_action(env_idx, action) for each env
    • Each env runs IK + mj_step × 25 independently
    • Returns batched (obs, reward, terminated, truncated, info)
Note: "Parallel" here means vectorized Python loop over envs, NOT multi-process/GPU parallelism. Each env has its own MuJoCo model/data pair. The parallelism is at the batch level for neural network inference (GR00T + actor), while physics stepping is sequential per env.

4. Two Eval Modes

A. Standalone Eval (eval_checkpoint.py)

One-shot evaluation of a specific checkpoint:

python -m resfit.rl_finetuning.scripts.eval_checkpoint \
  --checkpoint outputs/pnp_100ep_100k/best.pt \
  --perturb_table configs/pnp_common5_positions.json \
  --groot_checkpoint /path/to/groot/checkpoint-30000 \
  --eval_num_episodes 2 \
  --ema_alpha 0.9 \
  --action_scale 0.2 \
  --actor_hidden_dim 512 --critic_hidden_dim 1024 \
  --asymmetric_critic \
  --save_video --video_dir outputs/eval_videos

B. Async Eval (eval_async_mujoco.py)

Continuous polling loop — runs alongside training:

python -m resfit.rl_finetuning.scripts.eval_async_mujoco \
  --checkpoint_dir outputs/pnp_100ep_100k \
  --output_dir outputs/pnp_100ep_100k/eval_results \
  --groot_checkpoint /path/to/groot/checkpoint-30000 \
  --perturb_table configs/pnp_common5_positions.json \
  --eval_num_episodes 2 \
  --wandb_run_id <training_run_id>

Polls for eval_request_step*.pt files, evaluates, logs to W&B, deletes request files.

5. Success Criteria

  • terminated=True → success (from _is_success() in vec_env)
  • truncated=True → timeout (max_episode_steps reached)
  • Success condition: cube lifted ≥ threshold above initial height AND near bowl
  • Per-env success rate: sr_env{i} = successes / num_episodes for env i
  • Overall: success_rate = total successes / (num_envs × num_episodes)

6. GR00T + Residual Policy Inference

Per step: obs (images + state) │ ├──→ GR00T VLA (3B params) ──→ base_action (7D: pos3 + rot3 + grip1) │ ↓ (open-loop: runs every 16 steps) │ cached base_action │ ├──→ TD3 Actor (small MLP) ──→ residual_action (7D, scaled) │ └──→ combined = base_action + residual_action │ ▼ env.step(combined)

EMA smoothing: When ema_alpha > 0, actions are smoothed: a_t = α × a_{t-1} + (1-α) × a_raw
