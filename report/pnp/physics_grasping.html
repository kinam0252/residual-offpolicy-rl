03 - Physics-Based Grasping

Date: 2025-04-17 ~ 2025-04-18

Goal: Convert kinematic cube teleport grasping to physics-based simulation using mj_step()

1. Problem: Kinematic Grasping Was Not Physical

The original mujoco_vec_env_pnp.py used kinematic cube attachment:

  • When cube_tcp_dist < 0.20 (20cm!) and gripper closing → cube teleported to TCP position
  • No actual physics contact, no friction, no gravity on cube during grasp
  • Gripper visually passes through cube — unrealistic for sim-to-real transfer

Discovery: Same mechanism as infer_gr00t_mujoco.py reference code.

2. Physics Conversion Architecture

Key Changes in _apply_action()

# Old (kinematic):
data.qpos[joint_ids] = ik_solution
mujoco.mj_forward(model, data)
if close_enough: teleport_cube_to_tcp()

# New (physics):
1. Save qpos/qvel (scratch state)
2. Run IK on scratch → get target joint positions
3. Restore qpos/qvel
4. Set data.ctrl[actuator_ids] = target_values
5. mj_step(model, data) × 25 substeps (= 0.05s at dt=0.002)
6. Update grasp state from real contacts

Contact-Based Grasp Detection

  • Finger geom IDs discovered by body name ("left_finger", "right_finger") + group=3
  • _get_contacts(): Check data.contact for finger-cube geom pairs
  • Hysteresis: contact_count increments on contact, decrements by 2 on no contact
  • Grasped when contact_count >= GRASP_CONTACT_THRESHOLD (=1) and gripper closing

4. Sustained Grasp Problem

Core issue: Cube lifts 3-7cm but drops within ~30 steps (1.5 sec) during transport.

Pattern in every episode:

step  90: contact=[1,1,1] cc=10 grip_w=0.50  cube_z=0.019  ← grasped
step 120: contact=[1,1,1] cc=10 grip_w=0.50  cube_z=0.087  ← lifting!
step 150: contact=[0,0,0] cc=0  grip_w=0.50  cube_z=0.019  ← dropped
...
step 220: grip_w=0.90  ← gripper opens at bowl (cube already gone)

Approaches Tried

A. Physics Parameter Tuning (partial success)

  • Lighter cube (0.03kg) + torsional friction (0.5): Higher lift but still drops
  • Very sticky (friction=8.0, solref=0.008): Contact 5/5 but Lift 0/5 — too soft
  • Contact margin (2mm): Caused cube to launch at init (table collision)

B. Weld Constraint (in progress)

Added <equality><weld> constraint that activates on grasp detection:

  • Weld activates correctly (debug prints confirm)
  • Weld stays active while gripper closed (fixed deactivation bug)
  • Problem: Weld doesn't hold cube — constraint appears ineffective
  • Tried stiffening solref (0.001), solimp (1.0 1.0) — no improvement
  • Fixed eq_data index bug (was writing to [0:3] instead of [3:6] for relpose) — still no effect
Current Hypothesis: The IK scratch state save/restore pattern in _apply_action() may interfere with weld constraint. IK saves qpos → runs IK → restores qpos → sets ctrl → mj_step. The weld may be disrupted by this pattern.

Next approach: Instead of weld constraint, directly set cube qpos to track hand position during mj_step loop when grasped. This bypasses MuJoCo's constraint solver entirely.

5. Training Data Replay Setup

Created replay_training_data.py to verify physics sim with recorded demonstrations.

Cube Position Extraction from Parquet

  • Cube position = EEF (x,y) at gripper close event, z = CUBE_HALF_H (0.02)
  • Cube yaw = from gripper x-axis direction at close time
  • Bowl position = EEF (x,y) at gripper open event, z = 0
  • Gripper close threshold: gripper_width < 0.65

6. Current Best Configuration

# Finger actuators
kp = 5000, ctrl_range = [-0.01, 0.04], jnt_range = [-0.01, 0.04]
gripper_offset = -10mm (fingers close 10mm tighter than commanded)

# Friction (cube + fingers)
sliding = 5.0, torsional = 0.5, rolling = 0.1

# Cube
mass = 0.03 kg, condim = 6
solimp = "0.95 0.99 0.001", solref = "0.002 1"

# Simulation
PHYSICS_SUBSTEPS = 25, dt = 0.002s → 20 Hz control
