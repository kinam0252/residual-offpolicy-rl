05. Offline Data Collection & RL Training Pipeline

Residual TD3 학습을 위한 오프라인 데이터 수집부터 학습까지의 전체 파이프라인을 정리합니다.

1. 전체 파이프라인 개요

Step 1: Position Config 생성
configs/pnp_common5_positions.json — 학습 데이터에서 추출한 5개 기준 위치
↓
Step 2: Offline Data 수집
collect_offline_data_pnp.py — GR00T VLA base policy를 zero-residual로 rollout하여 transition 저장
↓
Step 3: Episode .npz 파일들
outputs/offline_data/pnp_{difficulty}_v4/ep_0000.npz, ep_0001.npz, ...
↓
Step 4: RL Training
train_residual_td3_mujoco_pnp.py — Online rollout + Offline replay buffer 혼합 학습
↓
Step 5: Evaluation
eval_checkpoint.py / eval_async_mujoco.py — 난이도별 position config로 평가

2. Position Config 체계

2.1 기준 위치 (Base Positions)

학습 데이터(33 episode)에서 추출한 5개 대표 위치가 모든 난이도의 기준점입니다.

파일용도내용
configs/pnp_common5_positions.json수집/평가 기준5개 고유 위치 × 2 (중복) = 10 entries
configs/pnp_sim33ep_positions.json전체 33ep 위치33개 episode별 cube/bowl 위치
configs/pnp_difficulty_spec.json난이도 설계 명세5개 base + perturbation 범위 정의

2.2 난이도별 설계 (Superset Design)

pnp_difficulty_spec.json에 정의된 공식 난이도 기준:

난이도envs 수구성위치 노이즈Yaw 노이즈
Easy55 base positions (고정)0 cm0°
Normal10Easy 5개 + perturbed 5개±2 cm±15°
Hard15Normal 10개 + hard perturbed 5개±5 cm±45°
핵심 설계: 난이도가 superset 구조 — Easy ⊂ Normal ⊂ Hard. 각 단계에서 이전 단계의 모든 env를 포함하고 더 어려운 env를 추가합니다.

2.4 Random Cube Range (perturbation 메커니즘)

난이도별 perturbation은 --random_cube_range JSON 인자로 제어됩니다:

# Easy: perturbation 없음
--random_cube_range  (생략)

# Normal: base 5 + perturbed 5 (±3cm, ±15° yaw)
--random_cube_range '[null, {"dx":[-3,3],"dy":[-3,3],"yaw":[-15,15]}]'

# Hard: base 5 + normal perturb 5 + hard perturb 5 (±6cm, ±45° yaw)
--random_cube_range '[null, {"dx":[-3,3],"dy":[-3,3],"yaw":[-15,15]}, {"dx":[-6,6],"dy":[-6,6],"yaw":[-45,45]}]'
JSON 배열 구조: [null, range1, range2, ...]
- null = base position 그대로 사용 (Easy에 해당)
- range1 = base에서 해당 범위만큼 perturb (Normal 추가분)
- range2 = base에서 더 넓은 범위로 perturb (Hard 추가분)
각 range마다 base 5개 위치 × 1개씩 = 5개 env 추가

출력:            outputs/offline_data/pnp_{difficulty}_v4

3.4 수집 과정

  1. Position config에서 cube/bowl 위치 로드
  2. random_cube_range로 perturbation 적용 → env별 위치 확정
  3. 각 env × num_episodes_per_env만큼 순차 rollout:
    • GR00T base policy로 action 생성 (residual = 0)
    • EMA smoothing 적용 (alpha=0.9)
    • MuJoCo env에서 step → transition 기록
  4. 에피소드별 ep_XXXX.npz 저장
  5. 전체 결과 result.json 저장

4.3 Online/Offline 혼합 학습 메커니즘

배치 구성 (offline_fraction=0.5, batch_size=256 기준): 
online_batch_size  = batch_size × (1 - offline_fraction) = 128
offline_batch_size = batch_size × offline_fraction        = 128
실제 학습 배치     = online 128 + offline 128 = 256 transitions

Offline Buffer 로딩 과정:

  1. offline_data_dir에서 모든 *.npz 재귀 탐색
  2. 각 npz에서 obs_state, obs_base_action, action, reward, done 로드
  3. next_obs를 shift로 재구성 (에피소드 경계 마스킹)
  4. TorchRL TensorDictReplayBuffer에 적재
  5. Buffer cache: 설정 해시로 캐시 → 재시작 시 빠른 로딩

학습 루프 핵심:

for global_step in range(total_timesteps):
    # 1) Online rollout: GR00T + residual → env.step()
    residual_action = actor(obs)           # 7D residual
    combined = base_action + residual      # 8D absolute
    next_obs, reward, done = env.step(combined)
    online_rb.add(obs, residual_action, reward, next_obs, done)

    # 2) Sample mixed batch
    online_batch  = online_rb.sample(128)
    offline_batch = offline_rb.sample(128)
    batch = concat(online_batch, offline_batch)  # 256

    # 3) Critic update (항상)
    critic_loss = MSE(Q(s,a), r + γ·minQ_target(s',a'))

    # 4) Actor update (critic_warmup 이후에만)
    if global_step >= critic_warmup_steps:
        actor_loss = -mean(Q(s, actor(s))) + l2_reg * ||actor(s)||²
주의: Critic warmup 기간에는 actor를 업데이트하지 않습니다. 이 기간 동안 critic이 먼저 안정적인 Q-value를 학습한 후 actor를 학습합니다.

Offline pretrain only 모드: --offline_pretrain_only 설정 시, critic warmup 이후 offline 데이터 사용을 중단하고 online 데이터만 사용합니다.

5. Residual Action 구조

5.1 Action Space

구분차원구성
GR00T Base Action8D absolute[pos_x, pos_y, pos_z, quat_w, quat_x, quat_y, quat_z, gripper]
RL Residual Action7D delta[Δpos_x, Δpos_y, Δpos_z, Δroll, Δpitch, Δyaw, Δgripper]
Combined Action8D absolutebase + residual → env에 전달

5.2 Residual 결합 방식

mujoco_residual_wrapper_pnp.py에서 처리:

# Position: 단순 덧셈
combined_pos = base_pos + residual_pos × action_scale

# Orientation: quaternion composition
residual_quat = euler_to_quat(residual_euler × action_scale)
combined_quat = base_quat ⊗ residual_quat

# Gripper: 덧셈 + clamp
combined_grip = clamp(base_grip + residual_grip, 0, 1)

6. Reward 함수

6.1 dense_clipped (기본 학습용)

5단계 shaped reward, [0, 1] 범위로 clip:

단계조건Reward
1. ApproachTCP→cube 거리 감소tanh(dist) 기반
2. Grasp접촉 감지contact 보너스
3. Liftcube_z 증가height 보너스
4. Transportcube→bowl 거리 감소distance 보너스
5. Placebowl 안 배치 성공success 보너스

6.2 Offline 수집용 reward (reward_uniform4)

collect_offline_data_pnp.py에서 별도로 계산하는 4단계 reward:

distance_reward = (1 - tanh(finger_cube_dist / 0.1)) × 1.0
contact_reward  = grasped × 2.0
height_reward   = (lift > 5mm) × tanh(lift / 0.1) × 100.0 × grasped
success_reward  = (lift ≥ 9.5cm) × 100.0 × grasped
reward 선택: 학습 시 --reward_type으로 사용할 reward를 결정합니다. offline 데이터에 여러 reward component를 저장해 두면, 나중에 reward function을 바꿔서 재학습할 수 있습니다.

7. Network Architecture

7.1 Actor

  • Input: observation.state (10D) + observation.base_action (7D) + 이미지 features
  • Image encoder → spatial features → MLP
  • Hidden dim: 256 (v2)
  • Output: Tanh → × action_scale (7D residual)

7.2 Critic

  • Input: obs + action (+ object_state if asymmetric)
  • Ensemble Q heads: 10개 (default)
  • Hidden dim: 256 (v2)
  • Policy Q: ensemble mean / min random pair / q1
  • Loss: MSE (기본), HLGauss / C51 옵션

학습 입력:

  → _load_offline_data()가 *.npz 모두 로드
  → TensorDictReplayBuffer에 적재
  → buffer_cache/offline_{hash}/ 에 캐시 저장

9.2 npz → TensorDict 변환

npz key→TensorDict key
obs_state→("obs", "observation.state")
obs_base_action→("obs", "observation.base_action")
obs_object_state→("obs", "observation.object_state")
action→("action",)
reward→("next", "reward")
done→("next", "done")
shift(obs_state)→("next", "obs", "observation.state")
next_obs 재구성: offline 데이터는 next_obs를 직접 저장하지 않습니다. 학습 시 obs[t+1]을 shift로 만들되, 에피소드 경계(done=True)에서는 마스킹합니다.
